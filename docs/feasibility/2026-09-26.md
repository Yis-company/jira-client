## Authentication finding

The documented Jira Cloud OAuth code exchange and refresh require a client secret. Atlassian documents limitations for standalone applications; no supported secretless Jira REST PKCE/device flow was established. Do not embed a shared secret in a desktop binary.

- [Jira OAuth](https://developer.atlassian.com/cloud/jira/platform/oauth-2-3lo-apps/)
- [Other integration security](https://developer.atlassian.com/cloud/jira/platform/security-for-other-integrations/)
- [Cloud app security requirements](https://developer.atlassian.com/platform/marketplace/security-requirements/)
- [Requirements FAQ](https://developer.atlassian.com/platform/marketplace/security-requirements-faq/)

Personal API-token calls are a documented technical use case. Distributing an app that collects teammates' tokens is not the same use case and conflicts with current app guidance. Rovo A2A's documented PKCE is for Rovo chat, not proof of Jira REST scope support.

Decision: Yi selected **Personal desktop-only pilot first**. This authorizes personal API-token onboarding and metadata inspection, with the token entered only into the native app and held in the OS credential store. Team onboarding is deferred; no shared server is introduced. Native authentication and the field compatibility checks still need evidence before dependent feature implementation.
